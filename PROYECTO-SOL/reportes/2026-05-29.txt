Reporte 2026-05-29

El día estuvo enfocado en dos frentes: primero terminar de estabilizar Alex WhatsApp (el bot de Crating Express) y luego actualizar el Strategist AI para que lea las keywords de G54 en vez de generarlas por su cuenta.

Con Alex, se retomó la sesión con varios bugs activos. El primero era el loop de medidas: el nodo de instrucciones le decía literalmente "Pide las medidas" sin verificar si el usuario ya las había dado, así que Alex las pedía una y otra vez sin importar lo que dijera el cliente. Se corrigió con una instrucción condicional: primero revisa si el mensaje actual tiene algún dígito y si es así lo guarda, y solo si no hay dígitos pregunta. El mismo patrón aplicó para el loop de fecha, donde el cliente decía "para el primero" y Alex no lo reconocía como fecha porque la instrucción no verificaba el mensaje actual antes de actuar.

El tercer bug era más profundo: la cotización nunca disparaba el paso POST_COTIZACION aunque el cotizador sí devolvía el precio. Se rastreó via la API de ejecuciones de n8n y se encontró que el nodo PATCH de Airtable devolvía 422 INVALID_MULTIPLE_CHOICE_OPTIONS porque el estado "Lead Caliente" no existe como opción válida en el campo Estado de Airtable. Al fallar ese PATCH, el campo cotizacion_enviada nunca se guardaba en Notas, así que el flujo nunca avanzaba a POST_COTIZACION. La corrección fue cambiar "Lead Caliente" por "Calificado", que sí es una opción válida. Junto con eso se corrigió el fallback del tipo de caja en el cotizador que usaba "cajon_cerrado" en vez de "cajones_cerrados".

Una vez estabilizado Alex, se discutió la estrategia de marketing para Crating Express considerando los agentes que ya están operativos. Ya tenemos el Content AI generando posts, el WhatsApp Engine convirtiendo consultas, y el Voice Agent capturando llamadas. Lo siguiente natural es activar el Strategist AI para definir la estrategia formal y que el Content AI la use como base en vez de operar con fallbacks.

El Strategist AI ya existía pero tenía dos problemas: el email de notificación tenía hardcodeado "risosadmi@gmail.com" como fallback aunque el perfil de la empresa en G54 ya tiene el correo correcto, y el agente generaba sus propias keywords en vez de usar las que ya están en G54 (que tiene 35 keywords activas con intención categorizada: local, comercial, informacional, transaccional).

Se actualizó el workflow a v1.1: se agregó el nodo "🔍 Obtener Keywords G54" entre Obtener Productos y Preparar Contexto, el nodo de preparación ahora agrupa las keywords por intención y se las pasa al prompt de Gemini con instrucción explícita de usarlas en vez de inventar nuevas, y se quitó el fallback de email hardcodeado. El workflow se subió a n8n via API y quedó en la posición correcta en la cadena. También se guardó el JSON actualizado en el repo.

Quedó pendiente ejecutar el Strategist AI por primera vez para generar la estrategia real de Crating Express. Para eso necesitamos el AGENT_TOKEN de G54 para que pueda guardar la estrategia en la API, o alternativamente ejecutarlo y capturar la estrategia desde el correo de notificación aunque no se guarde en G54. Una vez que exista la estrategia, el Content AI la usará automáticamente en la próxima generación de posts y el ciclo completo del Módulo 1 quedará operativo.

1. Objetivo del proyecto

Actualmente el agente Alex opera en un único número de WhatsApp (+1 786-788-0417) para una sola empresa: Crating Express. El objetivo es convertir este sistema en una plataforma multi-empresa donde diferentes compañías puedan tener su propio agente de WhatsApp con su propio número, personalizado con su catálogo, su tono de comunicación y sus datos de negocio — todo corriendo sobre la misma infraestructura de n8n.

En términos simples: En vez de tener un bot hecho a medida para una sola empresa, construimos un sistema donde podemos conectar a cualquier empresa en días, no semanas — cambiando solo el contenido, no la lógica.

Lo que cambia por empresa

  • Número de WhatsApp propio
  • Nombre y personalidad del agente
  • Prompt del sistema (comportamiento, tono, idioma)
  • Catálogo de productos o servicios
  • Preguntas frecuentes
  • Correos de notificación al vendedor
  • Mensajes de bienvenida y seguimiento

Lo que es igual para todas

  • Motor de IA (Groq con fallback)
  • Lógica de recopilación de datos
  • Detección de leads calientes
  • Estructura de follow-up
  • Webhook y flujo en n8n

2. Qué es el Tech Provider de Meta y por qué lo necesitamos

Meta (empresa detrás de WhatsApp) tiene un modelo donde distingue entre dos tipos de usuarios de la API:

Usuario directo (situación actual)

  • Una empresa registra su propio número
  • Gestiona su propia cuenta de WhatsApp Business
  • Solo puede usar la API para su propio negocio
  • Configuración manual por empresa

Tech Provider (objetivo)

  • Una empresa intermediaria gestiona múltiples clientes
  • Los clientes conectan su número a través de un flujo guiado (Embedded Signup)
  • El Tech Provider puede gestionar mensajes de todos los clientes
  • Escalable: nuevos clientes en horas, no semanas

El Tech Provider no es lo mismo que un BSP (Business Solution Provider) completo, que requiere contrato formal con Meta y cuotas de volumen. Lo que necesitamos es el nivel de Tech Provider con Embedded Signup, que está disponible para cualquier desarrollador verificado y permite onboardear clientes de forma autónoma.

Embedded Signup: Es el flujo que verá el cliente cuando quiera conectar su número. Similar a "Iniciar sesión con Facebook" — el cliente autoriza a nuestra plataforma a gestionar su número de WhatsApp en pocos clics, sin que nosotros tengamos que hacer nada manual.

Documentos a preparar para Meta

  • Documento de constitución de la empresa o registro mercantil
  • Número de identificación fiscal (EIN / RUC / NIT según país)
  • Descripción del caso de uso: qué tipo de mensajes enviará el sistema, con qué propósito
  • Muestra de mensajes: ejemplos reales del bot (confirmación de opt-in, respuesta a consulta, follow-up)
  • Flujo de opt-in: cómo el usuario final da su consentimiento para recibir mensajes

Punto crítico — Opt-in: Meta exige que el usuario haya consentido explícitamente recibir mensajes antes de que el sistema les escriba proactivamente (follow-up, notificaciones). Los mensajes reactivos (responder a lo que el cliente escribió primero) no requieren opt-in adicional.

4. Proceso paso a paso con Meta

01
Verificar el negocio en Meta Business Manager
Ir a Business Manager → Configuración → Verificación de negocio. Subir documentos de la empresa. Este proceso tarda entre 1 y 5 días hábiles. Sin esto, los demás pasos no avanzan.
02
Crear o revisar la Meta App con producto WhatsApp
En Meta for Developers, asegurarse que la app tiene el producto WhatsApp y está configurada en modo Live. Agregar los permisos whatsapp_business_management y whatsapp_business_messaging.
03
Solicitar acceso a Embedded Signup
Dentro de la app en Meta for Developers, buscar la sección "WhatsApp → Embedded Signup" y solicitar acceso. Meta revisa la solicitud en 1-3 días. Hay que describir el caso de uso: plataforma de automatización de WhatsApp para empresas.
04
Implementar el flujo de Embedded Signup
Una vez aprobado, se agrega un botón "Conectar WhatsApp" en nuestro panel de clientes. Este botón abre el flujo de Meta donde el cliente autoriza el acceso, registra su número y queda conectado a nuestra app automáticamente.
05
Configurar el sistema en n8n para el nuevo cliente
Una vez que el cliente completó el Embedded Signup, obtenemos su WABA ID y Phone Number ID. Con esos datos, creamos el registro en Airtable y el bot empieza a funcionar automáticamente.

5. Arquitectura del sistema en n8n

Situación actual (single-tenant)

Un webhook recibe mensajes de un solo número. El flujo asume que todos los mensajes son de Crating Express. La configuración del bot está en una sola fila en Airtable.

Nueva arquitectura (multi-tenant)

El mismo webhook de n8n recibe mensajes de todos los clientes. El sistema identifica a qué empresa pertenece cada mensaje usando el campo phone_number_id que Meta incluye en cada webhook. Con ese ID, carga la configuración específica de esa empresa y procesa el mensaje.

// Estructura del webhook de Meta (simplificada)
{
  "phone_number_id": "1083260611538246", // ← identifica la empresa
  "from": "50688001234",
  "text": { "body": "Hola, necesito una caja" }
}

Nodos nuevos en el flujo

NodoFunción
🔀 Identificar Empresa Lee el phone_number_id del webhook y busca en Airtable qué empresa corresponde a ese número
⚙️ Cargar Config Empresa Carga el prompt, catálogo, FAQs, emails de notificación y datos del negocio de esa empresa específica
🔍 Buscar Lead Busca el lead en la tabla de leads de esa empresa (filtrado por empresa_id + número de WhatsApp del cliente)
💬 IA con contexto empresa Misma lógica Groq actual, pero el prompt y el catálogo son los de la empresa identificada
📧 Notificar Vendedor Usa los emails configurados para esa empresa específica

Ventaja clave: Los nodos de IA, cotizador y lógica de negocio no cambian. Solo se agrega una capa de identificación al inicio que carga el contexto correcto. El resto del flujo funciona igual.

6. Estructura de datos por empresa

En Airtable se crean dos tablas nuevas (o se adaptan las existentes) para soportar múltiples empresas:

Tabla: Empresas_Clientes

Un registro por empresa cliente. Contiene la identificación y acceso a WhatsApp.

CampoTipoDescripción
Nombre_EmpresaTextoNombre del cliente (ej: "Crating Express")
Phone_Number_IDTextoID del número en Meta — es la clave para identificar mensajes entrantes
WABA_IDTextoID de la cuenta WhatsApp Business del cliente
Access_TokenTextoToken de acceso obtenido en el Embedded Signup para enviar mensajes en nombre del cliente
Config_IDLinkApunta al registro en WA_Config con el prompt y configuración del bot
ActivoCheckboxPara activar/pausar un cliente sin eliminarlo
Fecha_AltaFechaCuándo se conectó este cliente

Tabla: WA_Config (adaptación de la existente)

Ya existe para Crating Express. Se agregan campos para el catálogo y se vincula a Empresas_Clientes.

CampoDescripción
Empresa_IDLink a Empresas_Clientes — identifica a quién pertenece esta config
Nombre_AgenteNombre del bot para esta empresa (Alex, Sofia, Carlos, etc.)
Prompt_SistemaPrompt base del agente, con placeholder {{CATALOGO}}
Instrucciones_IAReglas de comportamiento adicionales
Catalogo_ProductosLista de productos/servicios de esta empresa (reemplaza a Airtable PRODUCTOS)
WA_Mensaje_BienvenidaMensaje para nuevos contactos
WA_FollowUp_24hMensaje de seguimiento a las 24h
WA_FollowUp_72hMensaje de seguimiento a las 72h
WA_FAQsPreguntas frecuentes del negocio
WA_Palabras_Lead_CalientePalabras que indican que el cliente está listo para cerrar
Email_VendedorCorreos para notificaciones de leads (puede ser múltiple)

Tabla: WhatsApp_Leads (adaptación)

Se agrega un campo empresa_id para separar leads por cliente.

Campo nuevoDescripción
Empresa_IDLink a Empresas_Clientes — para filtrar leads por empresa

El resto de campos (Estado, Historial_Mensajes, Datos recopilados, etc.) se mantienen igual.

Alternativa escalable: Si el volumen de leads crece mucho, considerar una tabla de leads separada por empresa o migrar a una base de datos relacional (PostgreSQL). Para las primeras 10-20 empresas, una sola tabla con empresa_id en Airtable es suficiente.

7. Cómo funciona el flujo de cada mensaje

Este es el recorrido completo de un mensaje desde que el cliente final escribe hasta que recibe respuesta:

1
Mensaje llega al webhook de n8n
Meta envía el mensaje a nuestra URL única. El payload incluye phone_number_id (identifica la empresa), el número del cliente y el texto del mensaje.
2
Identificar la empresa
n8n busca en la tabla Empresas_Clientes el registro cuyo Phone_Number_ID coincida. Si no existe, el mensaje se descarta o va a una cola de errores.
3
Cargar configuración de la empresa
Se carga el Prompt_Sistema, catálogo, FAQs, emails y Access_Token específicos de esa empresa.
4
Buscar o crear lead
Se busca en WhatsApp_Leads filtrando por empresa_id + número del cliente. Si no existe, se crea nuevo. Se carga el historial de conversación.
5
Preparar contexto para la IA
Se construye el prompt combinando: sistema de la empresa + catálogo real + historial + datos recopilados hasta ahora + mensaje actual del cliente.
6
Generar respuesta con IA
Groq procesa el mensaje. Si falla, va al fallback configurado. La respuesta incluye el mensaje para el cliente y los datos actualizados en JSON estructurado.
7
Enviar respuesta por WhatsApp
Se usa el Access_Token de la empresa (no el de Crating Express) para enviar el mensaje. Esto es lo que permite que el cliente final vea que el mensaje viene del número de su empresa.
8
Actualizar lead en Airtable
Se guarda el historial actualizado, el estado del lead y cualquier dato nuevo recopilado. Si es lead caliente, se envía notificación a los correos de esa empresa.

8. Proceso de alta de una empresa nueva

Una vez que el sistema está construido, agregar un nuevo cliente debería tomar menos de una hora de trabajo operativo:

Lo que hace el cliente

  • Completa el Embedded Signup (autoriza el acceso a su número)
  • Proporciona: nombre del negocio, catálogo, descripción, FAQs
  • Confirma el correo del vendedor para notificaciones
  • Aprueba el prompt del bot

Lo que hacemos nosotros

  • Crear registro en Empresas_Clientes con los datos de Meta
  • Crear registro en WA_Config con el prompt personalizado
  • Hacer prueba de mensajes para verificar comportamiento
  • Activar el flag "Activo" en la tabla

Datos mínimos para arrancar un cliente

Phone Number ID WABA ID Access Token Nombre de la empresa Rubro/industria Catálogo de productos/servicios Nombre del agente Correo del vendedor Tono de comunicación

9. Fases de implementación

FaseTareaPrioridad
Fase 1 — Meta Verificar el negocio en Business Manager, revisar el estado de la app actual, solicitar acceso a Embedded Signup Bloqueante
Fase 2 — Legal/Web Crear política de privacidad y términos de servicio en el sitio web. Describir el caso de uso para Meta. Bloqueante
Fase 3 — Datos Crear tabla Empresas_Clientes en Airtable, agregar campo Empresa_ID a WA_Config y WhatsApp_Leads Alta
Fase 4 — n8n Duplicar el workflow actual, agregar nodos de identificación de empresa y cargar config dinámico. Probar con Crating Express como primer cliente. Alta
Fase 5 — Onboarding Implementar flujo de Embedded Signup en una página web simple. Documentar proceso de alta de cliente. Media
Fase 6 — Primer cliente externo Alta de una segunda empresa (distinta a CE) como prueba real del sistema completo Media

Dependencia crítica: Las fases 1 y 2 dependen de aprobación externa (Meta). El tiempo estimado de respuesta de Meta para verificación de negocio es de 1 a 5 días hábiles. Para Embedded Signup, puede tomar hasta 2 semanas adicionales. Las fases 3 y 4 se pueden trabajar en paralelo mientras se espera a Meta.

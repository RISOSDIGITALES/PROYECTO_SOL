Tokens de diseño del reporte de Analytics

Colores, tipografía, logo y componentes reales usados en el reporte de Analytics RRSS (Opción 2, aprobada 29-jul-2026) — para que cualquier otro módulo de G54 que mande un reporte por correo use exactamente los mismos valores, sin reinventar la paleta cada vez.

Última actualización: 29 julio 2026
Fuente real: ANALYTICS MENSUAL V3-META REPORTE (n8n)
Regla de oro — por qué todo va en estilos inline
Nunca uses un bloque <style> ni variables CSS (--color) en un email. Confirmado en producción real el 28-jul-2026: Gmail y la mayoría de los clientes de correo no aplican bloques <style> de forma confiable — el resultado es un correo con colores y layout completamente rotos, aunque se vea perfecto en un navegador. La única forma confiable es style="..." inline en cada elemento, con tablas HTML (<table>) en vez de <div>+flexbox/grid para el layout general.
  • Los valores hex de esta página se muestran como referencia visual — al implementarlos en un email, se pegan literales en cada style="", nunca como variable.
  • El reporte real usa <table width="600"> como contenedor — 600px es el ancho estándar seguro para que no se corte en ningún cliente de correo.
Logo — lockup real
Growth 54 ai
No existe un archivo de imagen del logo — se construye con texto + un círculo de fondo blanco, para que funcione en cualquier cliente de correo sin depender de que cargue una imagen externa (muchos clientes bloquean imágenes por defecto hasta que el usuario las habilita).

Cómo reusar esto en otro reporte de G54 — copiá el bloque del header (logo + eyebrow + nombre + status strip) tal cual, cambiá solo el contenido dinámico (nombre de empresa, período, eyebrow de módulo). El resto de la paleta (tarjetas, badges, tipografía) ya es genérico y sirve para cualquier módulo — Analytics, SEO, SEM, Web — sin inventar una paleta nueva cada vez.

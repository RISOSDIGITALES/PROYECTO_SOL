1. imagen_url no persiste al guardar desde el panel
Panel › Editor de Posts › Guardar Cambios
Panel UI 🟠 Bloqueante

Al editar un post en estado borrador desde el panel, el campo de URL de imagen acepta input y muestra el preview visual correctamente. Sin embargo, al dar "Guardar Cambios" el valor no se persiste en el backend. La API devuelve siempre "imagen_url": null, lo que impide al Distribution AI publicar en Instagram — la Graph API exige imagen para posts de IG.

Cómo verificarlo
1
En el panel editar un post en estado borrador → pegar cualquier URL de imagen → clic en Guardar
2
Llamar GET /api/n8n/companies/1/rrss/posts con Bearer token → verificar que imagen_url ya no sea null
3
Si sigue siendo null → el formulario de Guardar no está enviando el campo al backend, o el backend lo ignora en el UPDATE
Impacto: Las ideas de Instagram aprobadas están retenidas por este motivo. Hasta que el campo guarde correctamente, ningún post de IG puede publicarse.
2. Endpoint GET /wa/leads sin implementar
API Backend — WhatsApp
Endpoint 🔴 P0

El Sales AI y el Community AI necesitan consultar leads existentes de WhatsApp para dar continuidad a conversaciones. El endpoint no existe — verificado en múltiples variantes de URL. Sin esto el motor de ventas no puede retomar conversaciones previas ni verificar si un número ya es lead.

Endpoint requerido
GET /api/n8n/companies/{id}/wa/leads
// Query params opcionales:
?phone=+17865556666   // filtrar por número (el más importante)
?status=activo

// Response:
{
  "leads": [
    {
      "id": 1,
      "phone": "+17865556666",
      "nombre": "Carlos Méndez",
      "status": "activo",
      "historial": "...",
      "ultima_actividad": "2026-07-01T20:00:00Z"
    }
  ]
}
Los endpoints de escritura ya existen: POST /api/agent/wa/leads y PATCH /api/agent/wa/leads/{id} — solo falta el de lectura para cerrar el ciclo.
3. Registro del Distribution AI en panel de agentes
Panel › Configuración › Agentes
Panel UI 🟡 P1

El Distribution AI (workflow IRCoya91PKPjpT1T) publica automáticamente los posts aprobados en FB/IG. Actualmente no aparece en el panel de agentes de G54, lo que dificulta el monitoreo y la trazabilidad desde el panel. Se activa por webhook POST /webhook/distribution-publish-g54.

Contexto: El agente consulta GET /api/n8n/companies/1/rrss/posts/to-publish, publica en la plataforma correcta (FB o IG según el campo platform del post), y luego llama POST /api/agent/rrss/posts/{id}/mark-published. Si falla, revierte el post a aprobado automáticamente para que pueda reprogramarse.

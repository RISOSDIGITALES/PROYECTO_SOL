02 Detalle
1. Botón borrar post en editor
Panel › Editor de Posts
Panel UI + Endpoint 🔴 P0

Durante pruebas del Content AI se generaron posts duplicados porque el agente se ejecutó varias veces antes de que la idea se marcara como "en proceso". Esos posts quedan en estado borrador y no hay forma de eliminarlos desde el panel. Se necesita un botón de borrar en la vista de edición del post.

Comportamiento esperado en el panel
1
En la vista de edición de un post, agregar botón "Eliminar post" (rojo, al pie del formulario o en el header)
2
Al hacer clic → modal de confirmación: "¿Eliminar este post? Esta acción no se puede deshacer."
3
Al confirmar → llama al endpoint DELETE → redirige al listado de posts
Endpoint necesario
DELETE /api/agent/rrss/posts/{id}
// Auth: Bearer AGENT_TOKEN
// Response:
{ "ok": true }

// Si no existe:
{ "ok": false, "error": "Post not found" }  // HTTP 404
Nota: Solo eliminar posts en estado borrador. Si el post está en aprobado o publicado se puede bloquear el borrado o mostrar advertencia adicional.
2. Campo imagen en editor de post
Panel › Editor de Posts
Panel UI 🔴 P0

El Content AI genera posts de texto. Para publicar en Instagram es obligatorio tener imagen — sin imagen el post no puede publicarse en IG (la Graph API devuelve error). El editor de posts actualmente no tiene campo para adjuntar o linkear imagen. Se necesita poder agregar la URL de la imagen desde el panel antes de aprobar el post.

Campo a agregar en el editor
image_url
Input de texto (URL) o uploader de imagen. La URL puede ser externa (Canva, Drive, Cloudinary) o subida directamente al storage de G54.
Comportamiento
Si el campo tiene valor, el Distribution AI lo usa para publicar en IG. Si está vacío, el post solo se publica en FB como texto.
Cómo lo lee el Distribution AI (ya implementado)
GET /api/n8n/companies/{id}/rrss/posts/to-publish — response actual
[
  {
    "id": 45,
    "content": "Texto del post...",
    "image_url": null,       // ← este campo ya existe en el response?
    "platform": "instagram"  //    si no existe, agregarlo
  }
]
Verificar: ¿El campo image_url ya existe en la tabla social_posts o equivalente? Si no, agregar columna VARCHAR(500) NULL.
3. Campos Hook y CTA editables en editor de post
Panel › Editor de Posts
Panel UI 🔴 P0

El Content AI genera el post con un framework de 8 pasos que incluye campos específicos: hook (primera línea que capta atención) y CTA (llamada a la acción al final). Cuando el cliente revisa el borrador y quiere ajustar solo esas partes, necesita poder editarlas sin reescribir todo el contenido. Actualmente el editor solo muestra el contenido completo como un bloque de texto.

Campos a exponer en el editor
hook
Primera línea / frase de apertura del post. Textarea corto (1-2 líneas). El Content AI lo genera siempre en el campo hook del JSON guardado.
cta
Llamada a la acción al final del post, incluye URL y hashtags. Textarea corto. El Content AI lo genera en el campo cta del JSON guardado.
Cómo los guarda el Content AI (referencia)
POST /api/agent/rrss/posts — body enviado por Content AI
{
  "company_id": 1,
  "idea_id": 12,
  "platform": "instagram",
  "content": "texto completo del post...",
  "hook": "¿Sabías que el 80% del daño en envíos...",   // ← campo separado
  "cta": "Cotiza tu embalaje hoy → cratingexpress.com", // ← campo separado
  "hashtags": "#embalaje #miami #crating",
  "keyword_principal": "embalaje industrial miami",
  "status": "borrador"
}
Verificar: Los campos hook y cta ya se guardan en la BD (el agente los envía). Solo se necesita exponerlos en el formulario de edición del panel para que el cliente pueda modificarlos.
4. Endpoint de lectura de leads WhatsApp
API Backend — nuevo endpoint
Endpoint 🔴 P0

El agente Marco (WhatsApp de Crating Express) guarda correctamente cada conversación vía POST /api/agent/whatsapp/inbound. El problema es que cuando el cliente escribe un segundo mensaje, el agente no puede recuperar el historial anterior porque el endpoint de lectura no existe. Resultado: Marco trata a cada mensaje como si fuera un cliente nuevo, pierde todo el contexto de la conversación y repite preguntas que ya hizo.

Endpoint requerido
GET /api/n8n/companies/{id}/wa/leads?phone={phone}
// Auth: Bearer N8N_TOKEN (lectura)
// Ejemplo: GET /api/n8n/companies/1/wa/leads?phone=%2B17867880417

// Response:
{
  "data": [
    {
      "id": 7,
      "contact_name": "Solange Torrez",
      "phone": "+17867880417",
      "estado": "En calificación",
      "historial": "Cliente: Hola, necesito una caja\nMarco: Buenos días Solange...",
      "datos": {
        "producto": "cajones cerrados",
        "medidas": "40x30x20 pulgadas",
        "fecha": "15 de julio",
        "tipo_cajon": "cajones_cerrados",
        "proteccion_extra": false,
        "correo_contacto": null
      },
      "created_at": "2026-06-20T14:08:00Z",
      "updated_at": "2026-06-26T14:08:00Z"
    }
  ]
}

// Si no hay lead para ese teléfono:
{ "data": [] }
Cómo lo usa el agente (flujo completo)
1
Llega mensaje de WhatsApp → agente llama GET /wa/leads?phone=+1786...
2
Si data[0] existe → carga historial y datos → Marco recuerda la conversación anterior
3
Si data[] vacío → cliente nuevo → Marco saluda e inicia recolección desde cero
4
Al responder → POST /api/agent/whatsapp/inbound actualiza el historial y los datos recolectados
Campo clave: historial debe ser el texto completo de la conversación (turnos anteriores). datos es el JSON de información recolectada durante la conversación. Ambos los guarda el agente vía el POST y los necesita leer vía este GET.
5. Registro del Distribution AI en panel de agentes
Panel › Configuración › Agentes
Panel UI 🟡 P1

El Distribution AI es el agente que publica los posts aprobados en Facebook e Instagram. Tiene trigger horario propio en n8n — no necesita que G54 lo llame. Sin embargo, para que G54 pueda notificarlo o activarlo desde el panel (por ejemplo, publicar inmediatamente cuando un post es aprobado en vez de esperar la siguiente hora), necesita estar registrado en la tabla de agentes.

Actualmente el panel de Configuración › Agentes no tiene una entrada para rrss_distribution_ai y no hay forma de registrarlo desde ahí.

Entrada a registrar
Registro en agent_endpoints (o tabla equivalente)
{
  "key": "rrss_distribution_ai",
  "name": "Distribution AI",
  "description": "Publica posts aprobados en Facebook e Instagram vía Graph API",
  "webhook_url": "https://n8n.mdarthurdigital.com/webhook/distribution-publish-g54",
  "trigger_type": "webhook",   // o "schedule" — el agente tiene ambos
  "module": "rrss",
  "active": true
}
Por qué ahora no publica automáticamente: Cuando un cliente aprueba un post por email, el estado cambia a aprobado en G54. El Distribution AI lo recoge en su próxima ejecución horaria. Si G54 pudiera hacer un POST al webhook al cambiar el estado, la publicación sería inmediata. Eso requiere que el agente esté registrado.
6. Editar plataforma asignada a cada idea
Panel › Banco de Ideas
💡 Sugerencia

El Strategist AI genera el banco de ideas y asigna automáticamente una plataforma a cada una (Facebook, Instagram, ambas). En ocasiones la sugerencia del agente no es la ideal — por ejemplo, asigna una idea de texto largo a Instagram cuando sería mejor para Facebook, o vice versa. No hay forma de cambiarlo desde el panel sin borrar la idea y volver a crearla.

Lo que se necesita
1
En la vista de edición o listado de ideas, agregar un selector de plataforma: Facebook / Instagram / Ambas
2
Al cambiar y guardar → actualiza el campo platform de la idea en la BD
3
El Content AI respeta ese valor al generar el post — ya toma la plataforma de la idea al ejecutarse
Impacto: Cambio simple de UX en el panel. No requiere nuevo endpoint — es una edición del campo platform que ya existe en la tabla de ideas, solo hay que exponerlo como editable.
